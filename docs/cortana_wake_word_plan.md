# Cortana 语音唤醒方案

## 目标

当前阶段先解决 **App 前台时稳定唤醒 Cortana** 的问题，不把后台真常驻、锁屏唤醒、系统级保活混进同一轮实现。

阶段目标：

1. 用户在 App 前台说出唤醒词时，Cortana 能稳定被唤醒。
2. 等待唤醒词时，界面有明确反馈。
3. 唤醒后进入短时指令窗口，用户能继续说出命令。
4. 手动语音输入中如果说出唤醒词，也能切入 Cortana，而不是误发给普通 LLM。

## 当前问题

旧实现使用 `speech_to_text` 模拟常驻监听：

```text
listen -> 静音超时 -> notListening/done -> 重启 listen
```

这个方案有三个问题：

1. `speech_to_text` 更适合短时听写，不适合长期等待唤醒词。
2. 静音后识别会话自然结束，导致状态反复抖动。
3. 手动语音输入会先暂停唤醒监听，因此在按住说话时说“嗨 Cortana”只会进入普通聊天链路。

## 当前阶段方案：前台常驻唤醒

### 总体架构

```text
Vosk 原生连续麦克风流
        ↓
等待唤醒词
        ↓
命中“嗨 Cortana”
        ↓
停止 Vosk 常驻监听，释放麦克风
        ↓
短时命令听写，最长 5 秒
        ↓
发送到 Cortana 对话链路
        ↓
处理结束后恢复 Vosk 常驻监听
```

### 职责拆分

#### 1. Vosk

负责前台常驻监听：

- Android 原生 `SpeechService`
- 持续接收麦克风流
- 返回 partial / result / final 文本
- Flutter 侧只判断是否命中唤醒词

#### 2. `speech_to_text`

只负责唤醒后的短时命令听写：

- 唤醒后最多等待 5 秒
- 收集用户真正想说的命令
- 不再承担长期等待唤醒词的职责

### 唤醒词匹配

当前支持别名：

- 嗨 Cortana
- 嘿 Cortana
- Hey Cortana
- Hi Cortana
- 你好 Cortana
- 嗨 科塔娜
- 嘿 科塔娜
- 嗨 小娜

后续若发现中文模型对英文 `Cortana` 识别不稳，优先建议把默认唤醒词收敛为中文，例如“嗨小娜”。

## 当前已完成的交互设计

### 1. 等待唤醒词

- 浮动图标轻微呼吸
- 设置页显示“正在监听唤醒词”

### 2. 已唤醒，等待用户继续说话

- 浮动图标切换为更强脉冲
- 图标表现为麦克风
- 最长等待 5 秒

### 3. 超时回退

- 5 秒内没有有效指令时，恢复等待唤醒词状态

### 4. 手动语音兼容

手动语音输入转写后，如果命中唤醒词：

- 不进入普通聊天 LLM
- 直接切换到 Cortana 唤醒流程

## 日志要求

需要完整记录以下事件：

- 常驻监听启动 / 停止
- 进入 / 退出等待唤醒词
- Vosk partial / result / final 识别文本
- 命中唤醒词
- 进入 / 退出等待用户说话
- 用户命令识别结果
- 5 秒超时回退
- Vosk 或短时听写错误

聊天区只展示用户真正需要看到的消息；底层识别状态不再刷屏。

## 当前阶段验收标准

### 功能

1. 打开“语音唤醒”后，状态显示为“正在监听唤醒词”。
2. App 前台静置时，聊天区不再反复刷识别状态。
3. 用户说“嗨 Cortana”后，浮动图标进入等待用户说话状态。
4. 用户继续说命令后，命令进入 Cortana 对话，而不是普通 LLM。
5. 用户按住语音输入说“嗨 Cortana，帮我……”时，也进入 Cortana。

### 日志

日志应能还原完整状态机，不需要依赖猜测：

```text
Vosk 常驻唤醒监听已启动
Vosk 常驻监听识别到: "嗨 cortana"
Vosk 常驻监听命中唤醒词
进入等待用户说话状态
等待用户说话识别到: "今天天气怎么样"
发送唤醒语音指令
```

## 后续阶段：后台真常驻唤醒

本阶段 **暂不实现**，后续再单独推进。

### 需要新增的能力

1. Android `ForegroundService`
2. 常驻通知
3. `foregroundServiceType="microphone"`
4. 对 Android 14+ 的 `FOREGROUND_SERVICE_MICROPHONE` 适配
5. App 切后台、锁屏、进程恢复后的监听生命周期管理
6. 电量、隐私提示、用户主动关闭入口

### 为什么后置

后台真常驻不是前台方案的简单延长，而是另一层系统工程：

- 生命周期不同
- 权限模型不同
- Android 平台限制更强
- 需要额外考虑用户感知、电量与隐私

因此先把前台唤醒做稳，再进入后台阶段，风险最低。

## 实施顺序

### Phase 1：前台唤醒收口

1. 完成 Vosk 常驻监听接入
2. 在真机验证唤醒词识别
3. 根据日志修正中文别名与误识别
4. 确认手动语音兼容分流
5. 收敛 UI 与日志噪音

### Phase 2：前台质量优化

1. 评估默认唤醒词是否改为中文
2. 优化误触发过滤
3. 必要时为 Vosk 增加更窄的词表策略

### Phase 3：后台真常驻

1. 设计 Android 服务层
2. 引入前台服务与通知
3. 处理后台麦克风权限限制
4. 评估耗电与系统杀活
